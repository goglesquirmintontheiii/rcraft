# Architecture Decision Records

Short, numbered, append-only. Supersede rather than edit.

## ADR-001 Language & toolchain
Rust stable (edition 2024, MSRV = latest stable at time of release), Cargo
workspace, `cargo xtask` for tooling. No nightly features.

## ADR-002 Graphics API: wgpu
wgpu gives Vulkan/DX12/Metal/GL from one code base, WGSL shaders, and `naga`
for translating Iris GLSL shader packs in Phase 4. Trade-off: Iris packs assume
OpenGL semantics (y-flip, uniform layouts, legacy GL state); the translation layer
is the main Phase 4 risk and is budgeted as such. Alternative rejected: raw OpenGL
via `glow` (simpler Iris parity, but worse multi-threading and no DX12/Metal).

## ADR-003 Windowing: winit 0.30
Stable, wgpu-compatible, Wayland + X11 + Win32. Will track 0.31 when released.

## ADR-004 UI: custom vanilla-style framework, not egui
Pixel parity with vanilla screens requires vanilla's layout/scaling/font rules;
egui's look and layout engine cannot reproduce them. egui may be used for
developer-only debug windows behind a feature flag.

## ADR-005 Assets are not redistributed
The repo ships an original CC0 fallback pack. Users import their own legally owned
vanilla assets at runtime for parity. See ROADMAP Decision 1 and CLEAN_ROOM.md.

## ADR-006 Registries generated from data
Blocks, items, biomes etc. are defined in `data/**/*.toml` and compiled into Rust
enums/tables by `rc_data/build.rs`. This keeps the 1000+ block definitions
reviewable, diff-able, and reusable by the Anvil/Bedrock converters and mod loader.

## ADR-007 World format: RCW
Custom format (docs/WORLD_FORMAT.md) rather than Anvil. Anvil import/export is a
converter (`rc_anvil`), not the native store.

## ADR-008 Releases built by GitHub Actions only
The development container has no Windows toolchain or GPU. All release artefacts
are produced from a tag by `release.yml` on GitHub-hosted runners (windows-latest
MSVC for the portable `.exe`, ubuntu-22.04 for the AppImage) so they are
reproducible and independent of any developer machine.

## ADR-009 Self-update via GitHub Releases + minisign
`latest.json` on each release lists per-platform asset URL, size, SHA-256, and a
minisign signature over the checksum file. The public key is compiled into the
binary; the private key lives only in the repository's Actions secrets.
Replacement uses the `self-replace` crate (rename-and-relaunch on Windows).

## ADR-010 Simulation is deterministic and single-threaded per world
Game logic runs on one sim thread at 20 TPS like vanilla so that block-update
order quirks (needed for redstone parity in Phase 3) are reproducible. Parallelism
is used for generation, meshing, lighting init and I/O, not for the tick itself.

## ADR-011 Java-mod support strategy (provisional)
Native WASM mods first; data-driven Java mods second; JVM bridge only as a
research spike. To be confirmed by the owner before Phase 5 (see ROADMAP).

## ADR-012 Seed-exact worldgen parity is a hard requirement
Decided 2026-11-02. All RNG and noise primitives are bit-exact reimplementations
from public documentation, and every generation stage is diff-tested against
reference captures taken from the owner's legally owned vanilla install. The
Anvil *reader* (`rc_anvil`) therefore ships in Phase 1 as test infrastructure;
the writer stays in Phase 2. Clean-room rule unchanged: reference data is
observed game *output*, never game code.

## ADR-013 Multiplayer must not depend on Microsoft credentials
Decided 2026-11-02. Offline-mode (`online-mode=false`) servers are supported with
no account at all; Microsoft login is an additive layer for online-mode servers
and is gated on the owner registering an Azure application when Phase 4 begins.

## ADR-014 Licence
Decided 2026-11-02. Code: MIT OR Apache-2.0. Original bundled assets: CC0-1.0.
Third-party assets are never bundled; vanilla assets are imported from the
user's own installation at runtime (ADR-005).

## ADR-015 Vanilla data-generator output is vendored as data
Decided 2026-11-02 (Phase 1). Seed-exact generation needs the exact worldgen
parameters (noise router, splines, noise octaves, biome parameter list,
surface rules, feature configs) and the block-state layout. These are the
output of Mojang's own data generator (`java -cp server.jar
net.minecraft.data.Main --all`), are pure data (no code, textures, sounds or
text), and are not shipped inside the game jar, so they cannot be read from
the user's install at runtime. They live in `data/vanilla/` (regenerated by
`tools/import_vanilla_data.py`) and are embedded compressed. Block physical
properties come from PrismarineJS minecraft-data (MIT). Textures, sounds,
fonts and language files remain user-imported (ADR-005).

## ADR-016 Decoration order is RustCraft's own
Overlapping features from neighbouring chunks depend on which chunk is
decorated first. In vanilla that order depends on player movement and worker
threads, so two vanilla runs of the same seed can differ there. RustCraft
decorates in a deterministic order (by distance from the requesting player,
ties by chunk coordinates). Parity tests therefore assert exactness for
biomes and terrain and treat feature overlaps statistically.

## ADR-017 Repository screenshots use the fallback pack
Decided 2026-11-02 (Phase 1). Screenshots committed under `docs/screenshots/`
are rendered with the procedural CC0 fallback pack, never with Mojang
textures, so the repository contains no Mojang art in any form. Screenshots
with the owner's vanilla assets may be shared with the owner directly but are
not committed.

## ADR-018 Phase 1 drops go straight to the inventory
Item entities need the entity system planned for Phase 2. Until then a block
broken in survival adds its drop directly to the inventory; blocks that need a
tool drop nothing, as with a bare hand in vanilla.

## ADR-019 Item entities replace direct-to-inventory drops
Decided 2026-11-02 (Phase 2), supersedes ADR-018. Broken blocks, mob drops
and `Q` spawn item entities with vanilla pickup delay, merging of nearby
equal stacks and a five-minute despawn. To keep large farms cheap, item
entities only tick physics while moving, merge checks run every 10 ticks,
and above 48 item entities in a chunk the merge radius widens from 0.75 to
4 blocks; above 96 the oldest are removed.

## ADR-020 Entities and block entities live in the chunk record
Decided 2026-11-02 (Phase 2). Entities are saved with the chunk they stand in
(on unload and on save) and restored when it loads, like vanilla's entity
chunks but inside the same RCW record, so a chunk and its contents are
written atomically. Payloads are JSON for now (see WORLD_FORMAT.md).

## ADR-021 Render distance 2–128 with a measured memory guard
Decided 2026-11-02 (Phase 2, owner request). Full-detail render distance goes
up to 128 chunks; LOD rendering (Phase 4) will extend the view to 1024
chunks. The memory limit is applied twice: an estimate caps the distance up
front (~250 MiB fixed + ~0.6 MiB per chunk), and every two seconds the engine
compares measured process memory with the limit, stepping the distance down
while over 105 % and back up while under 75 % (issue #1: 900 MB used with a
~400 MB limit).

## ADR-022 Sounds and entity textures come from the player's install
Decided 2026-11-02 (Phase 2), extends ADR-005. Sounds are read from the
launcher's hashed object store via the 1.21.1 asset index; entity, weather
and skin textures from the jar. With no install the game is silent and uses
procedurally generated stand-ins (`fallback_tex.rs`), never Mojang files.

## ADR-023 No anisotropic filtering; options are clamped and startup is guarded
Decided 2026-11-10 (0.2.1, issue #2). wgpu requires every filter to be
linear when anisotropy is above 1, but block textures use nearest
magnification to stay pixel-sharp; the Ultra preset's anisotropy 8 made
sampler creation a validation error, so every launch crashed until the data
folder was deleted. Anisotropy is now always 1 (the field stays in
`options.json` for compatibility). Options are clamped to valid ranges when
loaded, and a `startup.lock` marker detects a crash before the first frame:
the next launch sets `options.json` aside as `options.crashed.json` and
starts with defaults.

## ADR-024 Pipelined world generation and incremental streaming
Decided 2026-11-10 (0.2.1, issue #2). Carving (noise, surface, carvers;
~95 % of generation time, independent per chunk) is submitted to the worker
pool continuously, nearest targets first, with at most 2×threads+2 in flight
so lighting and meshing keep getting workers. The generation thread only
decorates (sequential, since features write into neighbours) and exports.
On the main thread the O(r²) request/unload scans run only when the player
changes chunk or the render distance changes, lighting/meshing candidates
come from a work set instead of every loaded chunk, disk loads are fed to the
pool a bounded number at a time, and the renderer indexes sections by chunk
column for culling and unloading. Measured with `--scene bench`.

## ADR-025 One dimension streamed at a time
Decided 2026-11-10 (0.2.1). A world folder keeps each dimension's regions in
`dim/<name>/`, and the world header's `dimension` field records where the
player is. Changing dimension saves, then reopens the world for the target
dimension; arrival finds the nearest portal or builds one. Multiplayer
(Phase 4) will need all dimensions live at once and will revisit this.

## ADR-026 Music streams; the short-sound cache is bounded
Decided 2026-11-10 (0.2.1, issue #2). Music and other `stream: true` sounds
are decoded while playing from their compressed bytes instead of being
decoded whole into f32 samples (~90 MB per track, previously cached forever
and copied again for playback). Short sounds play from a shared sample buffer
without copying, and the decoded cache is cleared above 8 M samples (32 MB).

## ADR-027 Memory guard scales the view distance proportionally
Decided 2026-11-10 (0.2.1, issue #2), refines ADR-021. Process memory before
the world opens is the fixed part (GPU driver, assets: ~300–380 MiB). When
measured memory exceeds the limit by 3 %, the render distance is scaled by
the square root of (limit − fixed) / (used − fixed), and the guard waits six
seconds for unloads to land before measuring again. The up-front estimate
is ~380 MiB fixed + ~0.15 MiB per loaded chunk (measured with
`--scene bench`). Limits below roughly 450 MiB leave room for only the
minimum render distance.
